# 実装計画: brw-pr-handoff

> 順序が依存を表す。`(P)` は直前の兄弟タスクと並行できるもの。判定層の入口（`brw guard` の共通化）は brw-branch-gate の 1.2 と共有するため、先に実装する側が作る。

- [x] 1. 基盤: 設定・判定の起点・公開記録
- [x] 1.1 (P) 片付けと本文言語の設定を宣言に加える
  - 宣言に片付けの有効・無効と本文の言語を持たせ、省略時は片付け有効・日本語とする。不正な値（型違い・未知のキー・未対応の言語）は宣言の不正として報告する。
  - 導入手順が宣言を新規に作るとき、片付けを有効にする既定値を書き込む。記入例と設定の資料も更新する。
  - 省略した既存の宣言が片付け有効として読まれ、`false` の明示だけが無効になり、不正な値が報告される。
  - _Boundary: 宣言の検証, setup_
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.6, 5.7_
- [x] 1.2 PR 作成の判定に「起点」を導入し、直接の作成だけを拒否する
  - 共通の判定に起点（既定はエージェント）を加える。エージェント起点の PR 作成（`gh pr create`・GitHub の API・MCP）は、規則に適合する場合も拒否し、`brw pr-template` と `brw pr` を案内する。BRW 自身の公開（計画時と実行時の 2 か所）だけが内部の起点を渡し、従来の判定を使う。
  - 内部の公開の計画と実行が従来どおり通り、エージェント起点の PR 作成が拒否される。起点を渡し忘れた経路は拒否側に倒れる。BRW 未導入のリポジトリは拒否しない。
  - _Boundary: 判定層, 公開（計画・実行）_
  - _Requirements: 1.1, 1.7, 6.3_
- [x] 1.3 push と PR の成功時に公開記録を保存する
  - push の成功時に push 先のリモート名と公開した OID を、PR の成功時に PR の URL と取り込み先を、作業状態に保存する。既存の結果の項目と互換を保つ。
  - 公開後に作業状態を読むと、リモート名・OID・URL・取り込み先が取り出せる。既存の公開の試験が変わらず通る。
  - _Boundary: 公開の状態記録_
  - _Requirements: 4.4, 4.6, 4.7_
- [x] 1.4 手順書の経路で直接の PR 作成を拒否する
  - brw-branch-gate の 1.2 で作る共通の入口を使い、`brw guard` が `gh pr create` などの直接の PR 作成を、このタスク群の 1.2 の判定で拒否する。
  - `brw guard "gh pr create …"` が拒否になり、案内に `brw pr` が含まれる。
  - _Depends: 1.2（このタスク群）、brw-branch-gate の 1.2_
  - _Requirements: 1.1, 1.6_

- [x] 2. 中核: 別コミット・本文・片付け
- [x] 2.1 (P) 未コミット変更の別コミット化を作る
  - 状態の全項目（未追跡ディレクトリは個々のファイルに展開し、改名は旧名と新名、ステージ済みを含む）を調べ、秘密らしい名前に当たるものがあれば何も commit せず停止し、無ければ 1 つの別コミット（決まった件名・ファイル一覧つきの本文）にする。変更が無ければ何も作らない。コミットの失敗では進まない。
  - 追跡済みの変更と未追跡が 1 つの別コミットになり、`.gitignore` の対象は含まれず、`.env` が混じると何も commit されず対象のファイル名が表示される。
  - _Boundary: tidy_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.6, 2.7_
- [x] 2.2 (P) PR 本文の雛形の解決と差し込みを作る
  - リポジトリの雛形（`.github/PULL_REQUEST_TEMPLATE.md`）を優先し、無ければ言語別の同梱の雛形（日本語・英語、節は概要・変更内容・検証・作業外の変更）を使う。作業外の変更の一覧（これから別コミットになる分と、既に別コミットになった分）と検証の要約（未通過なら明記）を、節の見出しがあれば差し込み、無ければ末尾に追記する。
  - リポジトリの雛形が優先され、言語が切り替わり、作業外の変更と検証が各節に入る。節の無い雛形では末尾に追記される。
  - _Boundary: pr-template（雛形）_
  - _Requirements: 2.5, 3.2, 3.3, 3.4, 3.5, 3.6_
- [x] 2.3 本文ファイルの置き場所と記入指示、`pr-template` の動作を作る
  - 本文ファイルを本体の worktree 置き場の配下（作業ツリーの外）に作り、記入済みなら上書きせずパスを案内する。標準出力に、BRW や呼び出し側を知らなくても使える短い記入指示（ファイルのパス・各節の書き方・事実だけを書く・参照する情報・書き終えた後の `brw pr` のコマンド）を出す。cc-sdd・`.kiro` の語を含めない。
  - 実行すると本文ファイルが作られ、記入指示が出力される。記入済みの本文は上書きされない。
  - _Boundary: pr-template（本文・指示）_
  - _Depends: 2.2_
  - _Requirements: 3.1, 3.7, 3.9, 6.2_
- [x] 2.4 (P) 片付けの安全確認と削除を共有の部品へ移す
  - `brw finish` が持つ安全確認と削除を独立した部品へ移し、遠隔の確認をリモート名の既存の取得に揃える。`brw finish` の挙動は変えず、移した後も既存の試験が通る。
  - 手動の `brw finish` が従来どおり動き、未 push・未コミットの worktree は残る。
  - _Boundary: cleanup（共有部）_
  - _Requirements: 4.1, 4.3, 4.5_
- [x] 2.5 PR 作成後の自動片付けと、状態の削除・回復を作る
  - 作成した PR の事実（URL・取り込み先・公開した OID・push 先のリモート名）を使い、ローカルの先端と遠隔の先端の一致、未コミットの無さ、本体が使っていないことを確認してから、worktree・ローカルブランチ・本文ファイルを削除し、最後に作業状態の記録を取り除く。他の記録が残るときは状態ファイルを残す。削除前に状態ファイルの場所をブランチの設定に残し、手動の `brw finish` も成功後に同じ手順で状態を削除する。
  - 確認できない・遠隔に無い・先端が違うときは片付けず理由を示し、削除後は子プロセスを走らせない。片付け後に、本体のパスと次の `brw create` を案内する。
  - 公開済みの作業で片付けが止まった場合も、再実行または `brw finish` で回復でき、状態ファイルが残らない。
  - _Boundary: cleanup_
  - _Depends: 1.3, 2.4_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9, 4.10, 4.11_

- [x] 3. 統合: `brw pr` と入口
- [x] 3.1 `brw pr` の調整役を作る
  - 事前確認（導入済み・開発ブランチ）、作業の特定（現在の作業、公開済みで片付けが残る作業、無ければ開始）、本文の確認、別コミット、準備・計画・公開、片付け（設定が有効なとき）を順に行う。済んだ段階を飛ばして再実行でき、準備後に HEAD が変わったときは準備をやり直す。承認待ちでは利用者の端末で実行する全文を案内し、成功後は片付けまで進む。
  - 開発ブランチへの取り込み（push だけで完了）は片付けず、設定が無効なときは片付けずに手動の手順を案内する。既存の PR は重複して作らない。
  - 偽の GitHub 接続で、準備から片付けまでが 1 回で通り、途中で止まっても再実行で続きから進む。
  - _Boundary: pr-flow_
  - _Depends: 1.1, 1.2, 2.1, 2.3, 2.5_
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 2.7, 3.8, 4.6, 4.7, 4.8, 4.9, 4.10, 5.5, 6.4_
- [x] 3.2 サブコマンドと本文ファイルの受け渡しを接続する
  - `pr` と `pr-template` を入口に加え、公開が本文ファイルを、作業ツリー配下の相対パスに加え、本文置き場の配下の絶対パスからも読めるようにする（実体パスの確認とリンクの逸脱の拒否は同じ基準）。
  - `brw pr-template` と `brw pr` が実行でき、本文置き場のファイルが `--body-file` で読まれ、置き場の外・リンクによる逸脱は拒否される。入口は 2 つだけである。
  - _Boundary: brw コマンド, 本文の読み取り_
  - _Depends: 3.1_
  - _Requirements: 3.9, 6.1_
- [x] 3.3 フックで信頼済みの `brw pr` の確認を省略する
  - 信頼済みの BRW の `pr` が、決まった形の引数で、宣言が push と PR の確認省略を有効にしているときだけ、ホストの確認を省略する。承認の要否・禁止は公開の内部が改めて判定する。本文置き場の絶対パスも許可する。それ以外は応答を返さない。
  - 信頼済みの `brw pr` だけが確認省略の対象になり、その他の形・信頼できない CLI は通常の承認に任せる。
  - _Boundary: judgeBash（publishCall）_
  - _Depends: 3.2_
  - _Requirements: 6.1_

- [x] 4. 検証と資料
- [x] 4.1 (P) 別コミットと本文の単体試験を書く
  - 別コミット（追跡と未追跡の混在・ignore 対象・秘密らしい名前・変更なし・コミット失敗）、本文（リポジトリ優先・言語・差し込み・節なしの雛形・記入指示が自己完結し特定の呼び出し側の語を含まない）を試験する。
  - 試験が通り、要件 2 と 3 の各受け入れ条件に対応する試験がある。
  - _Boundary: tidy, pr-template_
  - _Depends: 2.1, 2.3_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.9, 6.2_
- [x] 4.2 (P) 片付けの試験を書く
  - 未 push・未コミット・遠隔不在・OID 不一致・別のリモート・公開記録なしで残ること、安全なとき削除されること、状態の削除の順序と他の記録が残る場合、ブランチ削除の失敗後の `brw finish` による回復、手動の `finish` の挙動が変わらないことを試験する。
  - 各ケースで、worktree・ブランチ・状態ファイル・本文ファイルの有無が期待どおり。
  - _Boundary: cleanup_
  - _Depends: 2.5_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.10, 4.11_

  - 試験の一式が通り、要件 1・4・5・6 の各受け入れ条件に対応する試験がある。

  - 使い捨てのリポジトリと偽の GitHub 接続で、実際のエージェントが本文を本文置き場へ確認なしで書けること、`brw pr` の後に次の呼び出しが本体で動くことを確かめ、結果を記録する。
  - _Depends: 3.3_

  - 資料から一連の手順が読み取れ、評価ケースが定義の検証を通る。

- [x] 5. 実機の前提を、実際の git と GitHub で再現できる検証にする
- [x] 5.1 分岐元の取り込みと差の判定を、実際の git で再現する検証を用意する
  - bare remote の一時リポジトリで、分岐元が最新・リモートが先行・ローカルが先行・分岐・保護ブランチと差なし・未コミットの変更あり（衝突する場合としない場合）の各状態を作り、`fetch`・`merge --ff-only`・先行の数・保護ブランチとの差の数の結果を観測する（`poc/base-sync.sh` を検証基盤に取り込む）。
  - ローカルが先行していても `ff-only` が成功することを含め、各状態の観測結果が再実行できる形で残る。BRW 本体の実装には依存しない。
  - _Boundary: 検証基盤_
  - _Requirements: 1.8, 1.10_
- [x] 5.2 (P) 使い捨ての GitHub リポジトリで、分岐元を head とする PR を作れることを確かめる準備をする
  - 実環境検証の基盤（使い捨てのブランチ・認証・片付け）を使い、分岐元に当たる使い捨てのブランチと保護ブランチに当たるブランチの組を用意し、head を分岐元とする PR が GitHub の API で作成でき、差が無いときは作成できないことを観測する手順と後始末を用意する。
  - 手順が再実行でき、作った PR・ブランチが後始末で消える。通常運用のブランチを使わない。
  - _Boundary: 実環境検証_
  - _Requirements: 1.8, 1.10_

- [x] 6. 判定と案内を分岐元からの PR に対応させる
- [x] 6.1 分岐元から保護ブランチへの PR を、規則に適合する PR 作成として判定する
  - 共通の判定の PR 作成の規則で、取り込み元が恒常的な分岐元、取り込み先が保護ブランチの組を、規則に適合する作成として扱う。ほかの組（開発ブランチ間・宣言外・保護ブランチを取り込み元にする組など）の拒否は変えない。エージェント起点の直接の作成は、適合する場合も拒否のまま。
  - 各組の判定結果を判定の契約テストで確認できる。内部の公開（計画と実行）が従来どおり通る。
  - _Boundary: 判定層_
  - _Requirements: 1.4, 1.8_
- [x] 6.2 拒否の案内を、その状況で受け付けられる手順だけにする
  - 拒否の案内を組ごとに選ぶ関数にし、`brw pr` で作れる組（開発ブランチ→保護ブランチ・分岐元、分岐元→保護ブランチ）だけに `brw pr` を示す。作れない組には、作れない理由と、利用者が GitHub 上で PR を作成する手順（通信なしで作る作成画面の URL を含む）を示す。
  - `brw work start` が分岐元を拒否するときの案内は、分岐元から保護ブランチへの PR は `brw pr` で作れることを示す。案内はフック経路の文字数の制限に収める。
  - 各組の案内に、受け付けられない `brw` の手順が含まれないことと、作成画面の URL が含まれることを単体テストで確認できる。
  - _Boundary: 判定層、公開の入口_
  - _Depends: 6.1_
  - _Requirements: 1.11_

- [x] 7. 分岐元から保護ブランチへの PR を作る
- [x] 7.1 (P) PR の再利用・作成を、作業の記録に依存しない関数として切り出す
  - 公開の PR 処理から、同じ取り込み元・取り込み先のオープンな PR の探索、再利用、作成、作成後の照合を、リポジトリ・head・base・タイトル・本文・head の OID を受け取る関数として切り出して公開する。既存の公開の処理もこれを使い、挙動を変えない。
  - 既存の公開の試験が変わらず通り、切り出した関数を作業の記録なしで呼んで、再利用・作成・食い違いの停止を確認できる。
  - _Boundary: 公開（PR）_
  - _Requirements: 1.8_
- [x] 7.2 (P) 分岐元の取り込みと差の確認を作る
  - 分岐元の push 先のリモート名（`pushRemote` などを考慮し、`origin` 固定にしない）で、取得、先行の確認、`ff-only` による取り込み、保護ブランチとの差の数を求める部品を作る。先行は `ff-only` に任せず別に数える。先行・分岐・取得失敗・取り込み失敗・差なしは更新せず理由つきで止まる。
  - 作成先の決定（`--target` か、保護ブランチが 1 つのときそれ）も含め、5.1 の各状態と、`pushRemote` が `origin` 以外の場合を、一時リポジトリの単体テストで確認できる。
  - _Boundary: 分岐元からの PR_
  - _Depends: 5.1_
  - _Requirements: 1.9, 1.10_
- [x] 7.3 分岐元からの PR の調整役を作る
  - 本文の確認 → 取り込みと差の確認 → 既存 PR の探索 → 承認の判定 → PR の作成または再利用 → URL の報告の順に行う。作業の記録・別コミット・push・片付けを呼ばず、未コミットの変更があっても commit せず、含まれない旨を件数つきで表示する。
  - 承認が必要なときは PR を作らず、利用者の端末で実行する `--confirmed` つきの全文を案内して終了コード 1 で終わる。`--confirmed` は標準入力が端末のときだけ受け付け、端末でなければ何もせず拒否する。PR の作成には head の OID を渡して作成後の照合を働かせる。
  - 偽の GitHub 接続で、PR の作成・既存 PR の再利用・承認待ち・`--confirmed` の端末判定・再実行で PR が重複しないこと・作業の記録の状態ファイルが作られないこと・分岐元のブランチと作業場所が残ることを確認できる。
  - _Boundary: 分岐元からの PR_
  - _Depends: 6.1, 7.1, 7.2_
  - _Requirements: 1.8, 1.9, 1.10, 2.8, 4.12_
- [x] 7.4 `brw pr` の振り分けと `brw pr-template` を分岐元に対応させる
  - `brw pr` の事前確認で、現在のブランチが開発ブランチなら従来の流れ、恒常的な分岐元なら分岐元からの PR へ渡し、どちらでもなければ理由と取るべき手順を表示して止まる。
  - `brw pr-template` が分岐元でも雛形と記入指示を出し、作成元と作成先を示し、「作業外の変更」の節を該当なしとして扱う。
  - 開発ブランチでの `brw pr`・`brw pr-template` の既存の試験が変わらず通り、分岐元での振り分けと雛形の出力を試験で確認できる。
  - _Boundary: 調整、本文_
  - _Depends: 7.3_
  - _Requirements: 1.4, 1.8, 3.10_

# 調査記録: brw-pr-handoff（設計前の検証）

検証日: 2026-11-25。環境: Claude Code 2.1.329、Node.js 22。使い捨ての Git リポジトリと、既存の `scripts/` の読み取りで確かめた。

## 検証結果

| # | 確かめたこと | 結果 | 設計への影響 |
|---|---|---|---|
| 1 | 片付けで作業ディレクトリ（worktree）が消えた後、Claude Code の Bash の作業場所はどうなるか | 次の Bash 呼び出しで、**起動時のディレクトリへ自動で戻る**（消えた場所でのコマンドは失敗するが、その次から復帰）。`cd` の強制は不要 | 片付けは worktree の中から実行してよい。案内は「リポジトリ本体のパス」と「次の `brw create`」で足りる。同じコマンド内で消した後の `pwd` などは失敗しうるので、片付けは publish の最後に行い、後続のコマンドを続けない |
| 2 | `brw finish` の安全確認 | 既に実装済み: 未コミットの変更・本体が使用中・取り込み済みか（祖先関係・squash・`gh` の PR）・**リモートへの未 push commit**（`origin/<ブランチ>..`）。保護ブランチ向けの PR が見つかれば「取り込み済み」と扱う | 中止条件（未 push の commit）は再実装せず、`finishBlocker` を再利用する。既存 PR の再利用時も同じ判定で足りる |
| 3 | 作業状態の置き場所と、片付け後の残り方 | 状態は `<git-common-dir>/brw/work/<worktree ごとのハッシュ>.json`。**`git worktree remove` とブランチ削除の後も残る**（確認済み）。`brw work` に状態を消す操作は無い（`start/resume/restrict/ready/plan` のみ） | 「作業状態のクリア」には、状態ファイルの削除（または終端状態の記録）を新規実装する。`published` は現在の作業から外れる既存の遷移を使えるが、ファイル自体は残る |
| 4 | 直接の `gh pr create`・`gh api …/pulls` を既存の判定が識別できるか | 識別できる（どちらも `pr-create`）。複合コマンド（`&&` 付き）でも識別できる | 「直接の PR 作成を拒否して `brw pr` を案内する」判定は、既存の `evalPrCreate` に分岐を足すだけで実現できる。判定を確定できない形（未解決の引数など）の扱いは現行どおり安全側 |
| 5 | 未コミット変更の検出 | `git status --porcelain`（`finishBlocker` と `merge` が既に使用） | 作業外の変更の別コミット化は、追跡済み（`M`・`D`）と未追跡（`??`）に分けて扱える。無視対象は元から現れない |

## 設計で確定する方針（検証に基づく）

- 片付けの順序: push → PR 作成 → 作業状態を `published` にする → `finishBlocker` で確認 → worktree とローカルブランチを削除 → 状態ファイルを削除 → 案内の出力。片付けが止まったら、PR は作成済みのまま理由を報告し、再試行できるようにする。
- 既存 PR を再利用した場合も、`finishBlocker` の判定に任せる（push 済みで PR があれば片付ける）。
- `brw pr` が作業 ID なしで呼ばれたときは、現在のブランチの作業を探し、無ければ作業を新規に記録して進める（`brw publish` の入力を補う）。

## 決定事項

- 未追跡ファイルの別コミット化: `.gitignore` の対象は元から含めない。エージェントが止められない場合に備え、秘密らしい名前の接頭辞・パターンの一覧（`.env`・`*.pem`・`*credentials*` など）に当たるファイルが含まれるときは、含めずに publish を止める（防御の多重化）。
- 別コミットのメッセージ形式の既定: `chore: 作業外の変更（ボーイスカウト）`。含めたファイルの一覧を本文へ書く。
- 作業状態: 片付けで状態ファイルを削除する（履歴は PR が持つ）。削除は worktree とブランチの削除が成功した後だけ行い、片付けが止まったときは残して再試行できるようにする。片付けを経ない孤児の状態ファイルは今回の対象外とする。

## 統合の判断（Synthesis）

- **一般化**: 片付けは `brw finish`（手動）と `brw pr` の最後（自動）で同じ処理。安全確認（`finishBlocker`）と削除（`removeBranch`）を `cleanup.mjs` に出して共有する。自動側は「PR は今作った」という事実を渡し、`gh` の検索に依存しない。
- **Build vs Adopt**: 承認・計画・状態記録は既存の公開（`publish.mjs`）をそのまま使う。本文の雛形は、GitHub が標準で読む `.github/PULL_REQUEST_TEMPLATE.md` を優先して採用する。ラッパーは新しい仕組みを持たず、既存の段階を呼ぶだけ。
- **単純化**: 設定は 1 キー（`afterPublish.cleanup`）と言語の 1 キー（`pullRequest.language`）だけ。別コミットの対象は 1 種類（未コミットの変更すべて）で、秘密らしい名前だけを除外・停止の条件にする。本文の自動生成は作らない。

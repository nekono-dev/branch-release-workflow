# 要件定義書

## 概要

BRW を Claude Code と Codex の両方で使う開発者とエージェントが、どちらのハーネス（エージェントを動かす実行環境）でも同じ手順で導入・更新でき、作業を相手のハーネスへ引き継いでも同じスキル・同じ判定・同じフックの動作になるようにする。現状は Claude だけがプラグインとして導入でき、Codex は手動の clone とリポジトリごとの登録が要る。そのため導入・更新・worktree の扱いが分かれ、仕組みが複雑になっている。経緯と実機での確認結果は [brief.md](brief.md) に記録している。

## 境界の文脈

- **対象**　両ハーネスで共通の導入・更新の手順、Codex でのフック定義の取り違え防止、Codex での BRW のフックの信頼の登録と状態の診断、導入先リポジトリでの宣言、クラウド・CI・非対話の実行での導入、旧方式の削除。
- **対象外**　ブランチ・push・PR の判定ロジックと確認省略の条件（brw-enforcement が持つ）、GitHub Ruleset、プレビュー・配備、このリポジトリ自身の開発用フック、旧方式で導入済みの環境からの移行手段、Codex の公開ディレクトリへの掲載。
- **隣接する期待**　フックが受け取った操作の許可・拒否は brw-enforcement の判定に従い、この spec は「フックが両ハーネスで同じように届くこと」だけを扱う。Codex・Claude 側の製品としての承認や実行範囲の制限（サンドボックス）は変えない。フック 1 件ごとの信頼は Codex の仕様で、BRW のフック以外の信頼やプロジェクト単位の信頼には触れない。

## 要件

### 1. 両ハーネスで同じ手順で導入・更新する

**目的**　開発者が、利用するハーネスにかかわらず同じ手順で BRW を導入し、最新の版に更新できるようにする。

#### 受け入れ条件

1. When 開発者が Claude Code または Codex に BRW を導入するとき, the BRW shall 「マーケットプレイスの追加、プラグインの導入、`brw setup`、`brw check`」という同じ順序の手順で導入を完了できるようにする。
2. When 開発者がいずれかのハーネスで BRW を更新するとき, the BRW shall 同じ手順（プラグインの更新と `brw setup`）で更新を完了できるようにする。
3. The BRW shall 1 つのリポジトリ・1 つの版を、両ハーネスのプラグインの配布元として提供する。
4. The BRW shall 導入と更新の手順を、ハーネスごとの違いが対象の指定（コマンド名など）だけになるよう文書化する。
5. The BRW shall 両ハーネスの導入手順で、特定のホームディレクトリ配下への手動の clone や、導入先リポジトリごとの絶対パスの登録を求めない。

### 2. 作業をハーネス間で引き継いでも同じ動作にする

**目的**　開発者とエージェントが、作業を一方のハーネスから他方へ引き継いでも、追加の準備なしに同じ規則で続けられるようにする。

#### 受け入れ条件

1. When 同じ導入先リポジトリを Claude Code と Codex のどちらで開いても, the BRW shall 同じスキルの手順を利用できるようにする。
2. When 同じ操作が両ハーネスから実行されたとき, the BRW shall 同じ宣言と同じ判定規則で許可・拒否を決める。
3. While 導入先リポジトリの linked worktree（同じリポジトリから追加で作った作業用のチェックアウト）で作業している間, the BRW shall 本体のチェックアウトと同じようにフックを有効にし、worktree ごとの追加の有効化操作を求めない。
4. When `brw create` または `brw resume` が作業用の worktree を用意するとき, the BRW shall Codex のためだけの追加ファイルや除外設定を worktree やリポジトリに加えない。

### 3. Codex に Claude 用のフック定義を登録させない

**目的**　Codex の利用者が、Claude 向けの定義が誤って Codex のフックとして登録される事態を避け、Codex には Codex 向けの定義だけが届くようにする。

#### 受け入れ条件

1. When Codex に BRW のプラグインを導入したとき, the BRW shall Codex 向けのフック定義だけを Codex に登録させる。
2. When Claude Code に BRW のプラグインを導入したとき, the BRW shall 従来どおり Claude 向けのフック定義だけを登録させる。
3. The BRW shall 両ハーネスのフックが対象とする操作とイベントの範囲を、BRW の対応表として 1 か所に定め、両ハーネスのフック定義がその対応表と一致していることを自己テストで検証する。
4. If 両ハーネスのフック定義が対応表と食い違っているとき, then the BRW shall 自己テストを失敗させ、食い違いの箇所を表示する。
5. The BRW shall 配布物に、導入後に失われるおそれのあるシンボリックリンクを含めない。

### 4. Codex での BRW のフックの信頼を登録する

**目的**　Codex の利用者が、承認の画面を毎回操作しなくても、導入・更新の直後から BRW のフックを有効にできるようにする。

#### 受け入れ条件

1. When 利用者が Codex を対象に `brw setup` を実行したとき, the BRW shall Codex にプラグインが導入され有効になっていることを確認する。
2. When Codex に導入された BRW のフックが未信頼または古い内容の信頼であるとき, the BRW shall `brw setup` の中で、その時点の BRW のフックの定義に対する信頼を登録する。
3. The BRW shall 信頼を、BRW のフックの定義に限って登録し、BRW 以外のフック、コマンドの承認、実行範囲の制限、プロジェクト単位の信頼を変更しない。
4. When 信頼の登録が済んだとき, the BRW shall 登録したフックの件数と、残りの未信頼の有無を表示する。
5. When BRW のプラグインが更新されて信頼が外れたとき, the BRW shall 次の `brw setup` で信頼を登録し直す。
6. If 信頼を登録できないとき（Codex のフックが無効化されている、管理者の設定で管理対象のフックしか許されない、登録手段が使えない、対応していない版など）, then the BRW shall 理由を区別して表示し、利用者が Codex の `/hooks` で手動で承認する手順を案内する。
7. If 信頼の登録の途中で失敗したとき, then the BRW shall 登録済みの件数と未登録の件数を報告し、再実行で残りだけを登録できるようにする。
8. The BRW shall 既存の Codex の設定のうち、BRW の信頼の登録に関係しない項目を変更しない。

### 5. 導入状態を診断する

**目的**　開発者と管理者が、どのハーネスで BRW の強制が有効かを正しく把握し、更新後の強制の停止に気づけるようにする。

#### 受け入れ条件

1. When 利用者が `brw check` を実行したとき, the BRW shall ハーネスごとに BRW の強制が有効かどうかを表示する。
2. When Codex の BRW が有効でないとき, the BRW shall 理由を、プラグインの未導入、プラグインの無効、フックの未信頼、信頼が古い内容のまま（更新後に未登録）、対応していない実行環境のいずれかに区別して表示する。
3. When Claude Code の BRW が有効でないとき, the BRW shall 従来どおり理由を区別して表示する。
4. If 診断の途中で Codex の状態を取得できないとき, then the BRW shall 有効と推定せず、取得できなかったことと確認方法を表示する。
5. The BRW shall 旧方式（手動の clone、導入先リポジトリへの絶対パスの登録）の検出を、診断の対象にしない。

### 6. 導入先リポジトリで宣言する

**目的**　リポジトリの管理者が、リポジトリの設定ファイルだけで、両ハーネスの利用者に同じプラグインを使わせられるようにする。

#### 受け入れ条件

1. Where 導入先リポジトリが Claude Code 向けの設定でプラグインを宣言する, the BRW shall 従来どおり Claude Code の利用者にプラグインを案内する。
2. Where 導入先リポジトリが Codex 向けの設定でマーケットプレイスとプラグインを宣言する, the BRW shall 同じマーケットプレイスと同じプラグインを指す記述にする。
3. When 導入先リポジトリの宣言だけではプラグインが導入されない状態で `brw setup` または `brw check` を実行したとき, the BRW shall 導入に必要なコマンドを表示する。
4. The BRW shall 両ハーネス向けの宣言の記入例を、導入手順の文書に載せる。

### 7. クラウド・CI・非対話の実行でも同じ手順にする

**目的**　クラウド環境・CI・非対話の実行を使う開発者が、対話と同じ導入手順で同じ強制を得られるようにする。

#### 受け入れ条件

1. When クラウド環境または CI のセットアップスクリプトが導入手順を実行したとき, the BRW shall 対話と同じコマンド列で、利用者の操作なしに導入を完了できるようにする。
2. When 非対話の実行（`claude -p`・`codex exec`）で BRW のフックが有効な状態で操作したとき, the BRW shall 対話と同じ判定で保護ブランチへの commit・push を拒否する。
3. If 非対話の環境で信頼を登録できないとき, then the BRW shall 終了コードと表示で失敗を示し、強制が有効でないまま作業が進むことを見逃さないようにする。
4. The BRW shall 非対話の実行で、フックの信頼の確認を飛ばすオプションに頼らない手順を、既定の手順として文書化する。

### 8. 旧方式を削除する

**目的**　開発者が、導入の仕組みを 1 つだけ理解すればよい状態にする。

#### 受け入れ条件

1. The BRW shall Codex 専用の導入コマンド、導入先リポジトリごとの絶対パスの登録、worktree ごとの有効化の仕組み、および未導入の worktree を示す診断を、提供しない。
2. The BRW shall README・導入手順・スキル・関連する自己テストと評価ケースから、旧方式の手順と記述を取り除く。
3. The BRW shall 旧方式から新方式への移行手段を提供しない。
4. When 既存の Claude Code の導入を持つ利用者が BRW を更新したとき, the BRW shall その導入と宣言を変更せずに動作させる。

### 9. 通しで受け入れを確認する

**目的**　開発者が、導入から保護ブランチの拒否・作業ブランチでの作業までが、両ハーネスで実際に成立することを確認できるようにする。

#### 受け入れ条件

1. When 受け入れ確認を実施するとき, the BRW shall 利用者の既存の設定に影響しない一時的な環境に、新規に導入して確認する。
2. When Codex を指揮役として確認するとき, the BRW shall `gpt-6.2-sol`（思考の深さ medium）の `codex exec` で、導入、保護ブランチへの commit の拒否、作業ブランチでの作業、linked worktree での動作を確認する。
3. When Claude Code で確認するとき, the BRW shall 既存の `claude plugin validate` と `claude plugin eval` を通過する。
4. When 両ハーネスで確認したとき, the BRW shall 同じ操作に対して同じ判定結果になっていることを記録する。
5. If 受け入れ確認の途中で想定と異なる結果が出たとき, then the BRW shall 結果を記録し、成功したと報告しない。

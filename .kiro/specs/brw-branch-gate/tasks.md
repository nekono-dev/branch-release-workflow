# 実装計画: brw-branch-gate

> 順序が依存を表す（前のタスクに依存する）。`(P)` は直前の兄弟タスクと並行できるもの。`brw-pr-handoff` と判定層の入口を共有するため、1.2 は先に実装する側が作り、他方は再利用する。

- [ ] 1. 基盤: 判定の入力を整える
- [x] 1.1 作成・再開の分類結果に開始点と「ブランチだけ作る」を記録する
  - ブランチ作成の分類に、開始点（`git switch -c <名前> <開始点>` の開始点。無ければなし）と、切り替えない作成（`git branch <名前>`）かどうかを持たせる。判定の挙動は変えない。
  - 既存の分類の試験が変わらず通り、新しい項目が `switch -c`・`checkout -b`・`branch`・`worktree add -b` の各形で期待どおりに取れる（開始点あり・なしを含む）。
  - _Boundary: 判定の分類_
  - _Requirements: 1.1, 1.4, 3.1_
- [x] 1.2 手順書の経路（`brw guard`）が共通の判定を先に呼ぶようにする
  - `brw guard` が、旧来の commit・push の判定の前に、共通の分類と判定を呼び、作成・再開・PR 作成の拒否があれば案内を表示して終了コード 1 にする。拒否が無ければ従来の判定へ進む。
  - `brw guard "git switch -c dev/x"` が拒否になり、従来の commit・push の判定結果は変わらない。
  - brw-pr-handoff の「直接の PR 作成の拒否」が同じ入口を再利用できる形にする。
  - _Boundary: guard_
  - _Requirements: 1.6, 5.4_

- [ ] 2. 中核: ゲートの計画と案内、移動
- [x] 2.1 案内の共通書式を作る
  - 置き換え・拒否・EnterWorktree の案内を、1 行の結論・種別・次のコマンド・作業場所・自然文の説明の決まった書式で作る。特定の呼び出し側の語を含めず、資格情報らしい値は伏せる。
  - 同じ入力に同じ文面を返し、見出しだけでなく本文の文章だけで次の手順が読み取れる。
  - _Boundary: guidance_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 2.5_
- [x] 2.2 作成の置き換え計画を作る
  - 作成の入力を、置き換え・拒否のどちらかに決める。置き換えの条件（Claude Code・単独の操作・導入済み・命名規則に合う開発ブランチ・開始点が分岐元・配置先の一致）を判定し、置き換えるときは、本体への移動・`brw create`・作業場所の移動・案内の出力をつないだコマンドを、引用を正しく付けて組み立てる。
  - 追跡済みの未コミットの変更があれば拒否し、2 つの選択肢（そのまま作る・`--carry` で移す）を案内する。未追跡だけなら置き換え、残る件数を案内する。切り替えない作成は、作業場所を移さず、ブランチだけを作る形にする。
  - 規則外の名前・開始点・配置先・複合コマンド・Codex では、置き換えず、理由と次のコマンドを含む拒否になる。組み立てたコマンドを実際にシェルで解釈すると元の引数に戻る（空白・引用符を含むパスを含む）。
  - _Boundary: planGate_
  - _Depends: 1.1, 2.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.8, 1.9, 5.1_
- [x] 2.3 既存の開発ブランチへの切り替えを再開へ置き換える計画を作る
  - 既存のローカルまたはリモートの開発ブランチへの切り替えを、`brw resume` と作業場所の移動に置き換える。保護・分岐元への切り替えは従来どおり通常の承認に任せ、切り替え先を確認できなければ止める。
  - detached HEAD への移動は作成として扱わない。再開のコマンドが残っている worktree の場所へ移るコマンドとして組み立てられる。
  - _Boundary: planGate_
  - _Depends: 2.2_
  - _Requirements: 3.1, 3.2, 3.3, 3.4_
- [x] 2.4 EnterWorktree の判定を作る
  - `name` 指定は拒否し、`brw create` の後に `path` 指定で入る 2 手を案内する。`path` 指定は、`.claude/worktrees/` の配下で worktree 一覧に載る開発ブランチのものだけを許可し、それ以外・入力の不備・例外は拒否する。導入していないリポジトリは通す。
  - 各入力の組合せ（`name`・BRW の worktree への `path`・それ以外の `path`・両方・どちらも無い）が期待どおりに分かれる。
  - _Boundary: judgeEnterWorktree_
  - _Depends: 2.1_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 5.1, 5.3_
- [x] 2.5 (P) 未コミットの変更を移す処理を作る
  - 退避の置き場を使わず、変更を表すコミットを作り、新しい worktree へ適用し、内容（削除と実行権限を含む）を照合してから、元の作業ツリーの該当パスだけを戻す。戻す前に復旧用の参照を作り、違いを見つけたらそれ以降は戻さない。
  - 開始点が元の HEAD と異なる・適用が失敗・照合が一致しないときは、元を変えず、作った worktree とブランチを残さない。未追跡のファイルは移さず、一覧を返す。
  - 変更・削除・実行権限・バイナリ・ステージ済みと未ステージの混在が正しく移り、元から該当の変更だけが消える。
  - _Boundary: carryChanges_
  - _Requirements: 1.10, 1.11, 1.12, 1.13_
- [x] 2.6 `brw create` に `--carry` と失敗時の巻き戻しを加える
  - `--carry` で、移す処理を呼び、結果（移したファイル・移さなかったファイル・復旧の手順）を表示する。worktree 作成後の失敗では、宣言ファイルを先に元の場所へ戻してから worktree とブランチを削除し、戻せないときは worktree を残して手順を表示する。
  - `--carry` を付けない既存の挙動は変わらない。宣言ファイルを移した後の失敗を模擬しても、宣言ファイルが元に戻り、worktree もブランチも残らない。
  - _Boundary: brw create_
  - _Depends: 2.5_
  - _Requirements: 1.10, 1.11, 1.12, 1.13, 5.2_

- [ ] 3. 統合: フックと導入検査へ接続する
- [x] 3.1 フックの判定にゲートを接続する
  - 作成・再開の拒否を、ゲートの計画で置き換え（入力の書き換えと許可）または案内つきの拒否に変換し、EnterWorktree の入力も判定する。対象を確定できない拒否にも、案内の見出しと次のコマンドの行を付ける。応答は Claude Code にだけ書き換えを返す。
  - 同じ入力で、Claude Code は書き換えを含む許可を、Codex は拒否を返す。宣言の無いリポジトリでは何も返さず、照会だけの git コマンドは妨げない。
  - _Boundary: judgeBash, responseOf_
  - _Depends: 2.2, 2.3, 2.4_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 1.7, 2.1, 2.2, 2.3, 4.2, 5.1, 5.3, 5.4, 5.5_
- [x] 3.2 (P) フックの登録と導入検査に EnterWorktree を加える
  - プラグインのフック定義と、導入検査が期待するフックの一覧に、EnterWorktree の入口を加える（Codex の一覧は変えない）。
  - 入口の欠けた導入を検査すると、対象外の入口と有効にする手順が報告され、揃っていれば何も報告されない。
  - _Boundary: hook-install, hooks.json_
  - _Requirements: 6.1, 6.2_

  - 試験の一式（自己テスト）が通り、要件 1〜5 の各受け入れ条件に少なくとも 1 つの試験が対応する。

- [ ] 4.2 (P) 移す処理と巻き戻しの試験を書く
  - 移動の正常系、開始点のずれ・適用の失敗・照合の不一致での巻き戻し、取り除きの直前の書き換え、未追跡の扱い、作成後の失敗での宣言ファイルの復元を、一時リポジトリで試験する。
  - 各ケースで、元の作業ツリーの内容が期待どおり（変わらない、または移した分だけ消える）であり、worktree とブランチの有無が一致する。

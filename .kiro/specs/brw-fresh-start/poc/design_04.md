- 対象: 期限切れのときに外部コマンドの子孫プロセスまで止められるか（要件 3.3・3.5）、更新で書き換わるファイルを実行中のコードが読む場面を作らないこと（実現性の記録の前提 5・6）
- 段階: design

# PoC design_04: 子孫プロセスの打ち切りと静的 import の安定性

## 実施内容
一時ディレクトリの Node.js スクリプトで次を観測した（スクリプトと出力は管理対象に残していない）。
1. `spawnSync("sh", ["-c", "sleep 301 & wait"], { timeout: 500, killSignal: "SIGKILL" })` の後、孫の `sleep 301` が生き残るか。
2. `spawn("sh", ["-c", "sleep 302 & wait"], { detached: true })` を新しいプロセスグループで起動し、500 ms で `process.kill(-pid, "SIGKILL")`（グループ全体）した後、孫の `sleep 302` が生き残るか。
3. `import { v } from "./mod.mjs"` した直後に `mod.mjs` をディスク上で書き換え、(a) 実行中のプロセスが返す値、(b) 起動し直した子プロセス（動的に読み込む）が返す値を比べた。

## 実施日
2026-11-28

## 環境と版
Node.js 22.16.0、Linux（Ubuntu）。

## 結果と仕様への反映
1. `spawnSync` の `timeout` は直接の子（`sh`）だけを止め、**孫の `sleep 301` は生き残った**（生存数 1）。→ `spawnSync` の期限切れでは、`claude` や git が起動した子孫が更新を続ける恐れがある。
2. `detached: true` で新しいプロセスグループにして、グループ全体を `SIGKILL` すると、**孫まで止まった**（生存数 0）。`close` イベントは `signal: "SIGKILL"` で届く。→ `proc.mjs` は非同期の `spawn`（`detached: true`）で実行し、期限になったらグループ全体を打ち切って、終了を待ってから結果を返す。
3. (a) 静的 import の後にファイルを上書きしても、実行中のプロセスは古い値（`old`）を返し続けた。(b) 起動し直した子は新しい値（`new`）を読んだ。→ 更新の後に旧プロセスが行うのは「子の起動と終了を待つ」ことだけにして、ファイルを読まない設計にすれば、更新で書き換わるファイルを旧コードが読む場面は生じない。

## 確かめられなかったこと
- `claude` が `setsid` などで自らプロセスグループを離れて子孫を作る場合（グループの打ち切りでは止まらない）。→ 期限切れの後に導入の記録とファイルの状態を読み直し、事実に基づいて案内する（設計の失敗時の契約）。
- Windows でのプロセスグループの打ち切り。

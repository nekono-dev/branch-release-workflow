- 対象: 接続はできるが応答しない配布元に対して、待ち時間の上限で確実に打ち切れるか（要件 3.5、実現性の記録の前提 6）
- 段階: design

# PoC design_03: 応答しない配布元の打ち切り

## 実施内容
接続を受け付けるだけで何も返さない TCP サーバー（ポート 8767）を立て、Node の `child_process.spawnSync("git", ["ls-remote", "http://127.0.0.1:8767/x.git", "HEAD"], { timeout: 2000, killSignal: "SIGKILL", env: { GIT_TERMINAL_PROMPT: "0" } })` を実行して、戻りまでの時間と結果を測った。

## 実施日
2026-11-28

## 環境と版
Node.js 22.16.0、git 2.43.0、Linux（Ubuntu）。

## 結果と仕様への反映
- 2003 ms で戻り、`status: null`・`signal: "SIGKILL"`・`error.code: "ETIMEDOUT"` だった。上限（2000 ms）で子プロセスが確実に打ち切られ、結果は「失敗」として判別できる。
- → 応答しない相手は上限の時刻で確実に失敗として判別できる。ただし `spawnSync` の `timeout` は直接の子だけを止め、子孫は残る（`poc/design_04.md` の 1）。最終的な方式は、非同期の `spawn` とプロセスグループごとの打ち切り（`poc/design_04.md` の 2）。認証の入力待ちを防ぐため `GIT_TERMINAL_PROMPT=0` を付ける。打ち切りは「最新を取得できない」（要件 3.1・3.5）と扱う。

## 確かめられなかったこと
- 応答が遅いが止まらない通信（少しずつ返す配布元）。上限は全体の経過時間で切るため、同じ方式で打ち切れる見込み。
- Windows での子プロセスの打ち切り。

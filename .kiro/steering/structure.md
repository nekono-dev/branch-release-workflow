# プロジェクト構成

## 実行入口と共通ロジック

ルートの `SKILL.md` にエージェント向けの作業手順を置き、実際の操作と判定は `scripts/` に集約する。`brw.mjs` はサブコマンドやフックの入出力と操作の流れを担当する。宣言の検証、ブランチの照合、Git の照会など、複数の操作で共有する処理は `lib.mjs` に置く。`hooks/` のフック定義は CLI の呼び出しを担う。

## プレビューと配備

- `scripts/providers/` にプレビュープロバイダーを置く。入口の `index.mjs` が宣言に合うプロバイダーを選び、URL を組み立てる。固有の外部連携は各プロバイダーの検査、workflow 生成、後始末の処理に置く。
- `scripts/deploy/` に配備先の設定生成と検査を置く。プレビューと配備の両方で必要な設定生成手順は、配備側の共通処理を使う。

## 利用者向け資料と検証

宣言の仕様や導入手順は `references/` に、再利用できる宣言例は `assets/` に置く。cc-sdd の開発仕様は `.kiro/specs/` で機能ごとに要件・設計・タスクをまとめる。CLI と判定処理の自己テストは `tests/`、エージェントの操作手順の評価ケースは `evals/` に置く。

## 命名と import

スクリプト名とサブコマンド名は `install-codex.mjs`、`render-wrangler` のような kebab-case を使う。関数名は `loadConfig` のような camelCase とし、標準モジュールには `node:`、リポジトリ内のモジュールには拡張子付きの相対パスを使う。

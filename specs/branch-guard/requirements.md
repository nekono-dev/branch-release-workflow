# ブランチ運用の強制 要件定義書

## 1. 目的

本番向けブランチでの直接作業を防ぎ、作業ブランチで作業させる。運用の正本はリポジトリ内の宣言ファイルとし、判定は文章ではなく Claude Code のフックが機械的に行う。スキルとフックは Claude Code のプラグインとして配り、リポジトリへのコピーなしに、手元・クラウドセッション・CI のどこでも同じ版で動くようにする。

## 2. スコープ

### 2.1 対象

- 宣言ファイルの読み込みと検証。
- commit と push の前に行うブランチの判定。
- 作業ブランチの命名規則の検証と作成。
- 切り出し元へ取り込まれた作業ブランチの片付けと、作業の再開。

### 2.2 対象外

- ブランチの作成を止める判定。
- Bash の git コマンド以外の経路で行う操作の判定。

## 3. 前提

- なし

## 4. 機能要件

- FR-1: 宣言ファイルから作業ブランチ・保護ブランチ・分岐元・命名規則を読み込み、不正な値を検出する。
- FR-2: 保護ブランチ、または宣言にないブランチでの commit と push を拒否する。
- FR-3: 宣言ファイルがないリポジトリでは判定しない。宣言が不正、ブランチを特定できない、または全ブランチの push を指定したとき、利用者へ確認する。
- FR-4: push の送り先を指定する引数から実際に更新されるブランチを求めて判定する。
- FR-5: 命名規則に合う作業ブランチだけを作成し、規則に合わない名前を拒否する。
- FR-6: 切り出し元ブランチへ取り込まれた、または保護ブランチへの PR がある作業ブランチの worktree とローカルブランチを消す。取り込まれていない、commit していない変更がある、または push していない commit があるときは何も消さない。
- FR-7: 作業ブランチの続きを始めるとき、ローカルに無ければリモートから取得し直して worktree を作り、残っていればリモートの更新を早送りで取り込む。
- FR-8: リポジトリの設定でプラグインを有効にしているのに宣言ファイルがないとき、宣言を作るまで commit と push を拒否する。
- FR-9: 宣言ファイルをリポジトリに登録（commit）させる。整合検査は未登録の宣言を誤りとして報告し、作業ブランチの作成は分岐元に無い宣言を新しい worktree へ移して、その作業ブランチで登録できるようにする。

## 5. 非機能要件

- NFR-1: フックの判定は、1回あたり 1 秒以内に終える。
- NFR-2: スクリプトが依存する外部パッケージは 0 件にする。

## 6. 受け入れ条件

- AC-1 (FR-1): 作業ブランチの一覧が空の宣言を読み込むと、不正として報告される。
- AC-2 (FR-2): 保護ブランチ上で commit を判定すると、拒否される。
- AC-3 (FR-3): 宣言ファイルのないリポジトリで commit を判定すると、許可が返る（判定しない）。宣言が不正なリポジトリで判定すると、確認が返る。
- AC-4 (FR-4): 作業ブランチから保護ブランチへ送る push を判定すると、拒否される。
- AC-5 (FR-5): 命名規則に合わない名前でブランチの作成を指示すると、作成されずに終了コード 1 で終わる。
- AC-6 (NFR-1): 一時リポジトリでの判定 16 件が、合計 10 秒以内に完了する。
- AC-7 (NFR-2): スクリプトの import が Node 標準モジュールと相対パスだけである。
- AC-8 (FR-6): push しただけで切り出し元へ取り込まれていない作業ブランチの片付けを指示すると、worktree が残って終了コード 1 で終わる。切り出し元へ取り込まれた後（squash merge を含む）に指示すると、worktree とローカルブランチが消える。
- AC-9 (FR-7): 片付けた作業ブランチの再開を指示すると、リモートの commit を持ち、リモートを追跡する worktree が作られる。worktree が残っている作業ブランチの再開を指示すると、リモートに積まれた commit が取り込まれる。
- AC-10 (FR-8): `.claude/settings.json` でプラグインを有効にし、宣言ファイルのないリポジトリで commit を判定すると、拒否される。無効にしていれば判定しない。
- AC-11 (FR-9): 未登録の宣言があるリポジトリで整合検査を指示すると、終了コード 1 で終わる。作業ブランチの作成を指示すると、宣言が新しい worktree へ移り、そこで commit すると整合検査を通る。

# 配備先の宣言と設定の生成 要件定義書

## 1. 目的

本番用と開発用（プレビュー先）の Worker を分けて配備できるようにする。配備先ごとのブランチ・Worker 名・公開先（独自ドメインか workers.dev か）を宣言ファイルに書き、テンプレートから wrangler 設定を生成する共通部分と、配備用 workflow の雛形を提供する。運用者ごとに異なる値（ドメインなど）は変数で参照させ、スキルにもリポジトリにも直書きさせない。

## 2. スコープ

### 2.1 対象

- 宣言ファイルの配備先（`deploy`）の読み込みと検証。
- 宣言の値に含まれる変数の解決。
- テンプレートから配備先ごとの wrangler 設定を生成すること。
- 生成後にリポジトリ固有の加工を行うコマンドの呼び出し。
- 配備用 workflow 雛形の生成。
- 配備先の宣言と設定の整合検査。

### 2.2 対象外

- リポジトリ固有の加工の中身（D1・R2 の名前の変更、シークレットの登録、マイグレーションなど）。
- Cloudflare 側の実際の状態の検査。
- wrangler の environments（`env`）や複数の設定ファイルを使う分け方。

## 3. 前提

- 前提: branch-guard — 宣言ファイルの読み込みと保護ブランチの判定を使う。
- 前提: preview — プレビュー先の配備先と配信方式の判定を使う。

## 4. 機能要件

- FR-1: 宣言の `deploy` から provider・テンプレート・生成先・加工コマンド・取得元・配備先を読み込み、不正な値を検出する。
- FR-2: 宣言の値の `${変数名}` を、環境変数、無ければ GitHub Variables から解決する。
- FR-3: 指定した配備先について、テンプレートの Worker 名・独自ドメインの route・workers.dev 関連キー・プレビューの設定を宣言どおりに書き換えた wrangler 設定を生成する。
- FR-4: 変数が解決できないとき、テンプレートが無い・読めないときは、生成先を書かずに失敗する。
- FR-5: 加工コマンドを宣言したときは、生成の後に配備先名と生成先を渡して呼び、その失敗を生成の失敗として返す。
- FR-6: 配備先ごとのブランチへの push で、BRW の取得・設定の生成・ビルド・配備を行う workflow 雛形を出力し、既存のファイルは上書きしない。
- FR-7: 雛形は宣言の取得元から BRW を取得し、宣言で参照する変数を GitHub Variables から渡す。
- FR-8: 配備先のブランチが保護ブランチに含まれないとき、生成先が git に登録されているとき、配備用 workflow が無いときに警告する。

## 5. 非機能要件

- NFR-1: `deploy` の無い宣言では、従来どおりルートの wrangler 設定を直接使い、挙動を変えない。

## 6. 受け入れ条件

- AC-1 (FR-1): 配備先が 1 件も無い、ブランチが無い、provider が不明な `deploy` が、宣言の誤りとして報告される。
- AC-2 (FR-2): `${SITE_HOST}` を含む値は、環境変数 SITE_HOST があればその値に置き換わり、環境変数も GitHub Variables も無ければ未解決として扱われる。
- AC-3 (FR-3): 独自ドメインのある配備先の生成結果では、Worker 名が宣言の値になり、独自ドメインの route があり、workers_dev と preview_urls が false になる。
- AC-4 (FR-3): workers.dev 配信のプレビュー先の生成結果では、preview_urls が true になり、previews が置かれる。独自ドメイン配信のプレビュー先では route に previews_enabled: true が付く。
- AC-5 (FR-3): テンプレートにある独自ドメインでない route は生成結果に残り、独自ドメインの route は宣言の値で置き換わる。
- AC-6 (FR-4): 未解決の変数がある配備先の生成は、生成先を書かずに終了コード 1 で終わる。
- AC-7 (FR-5): 加工コマンドが非ゼロで終わると、生成も非ゼロで終わる。加工コマンドには配備先名と生成先のパスが渡る。
- AC-8 (FR-6): 配備用の雛形は、宣言の全配備先のブランチを push の対象とし、既存の deploy.yaml を上書きしない。
- AC-9 (FR-7): 雛形に、宣言の取得元の clone と、宣言で参照する変数の受け渡しが含まれる。
- AC-10 (FR-8): 保護ブランチに無いブランチを持つ配備先と、git に登録された生成先が、警告として報告される。
- AC-11 (NFR-1): `deploy` の無い宣言で、従来の検査と wrangler-config の結果が変わらない。
